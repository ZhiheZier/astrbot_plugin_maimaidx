# astrbot_plugin_maimaidx

[![python3](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/)
[![License](https://img.shields.io/badge/license-MIT-blue.svg)](https://opensource.org/licenses/MIT)

基于 [AstrBot](https://astrbot.app) 框架的街机音游 **舞萌DX** 查分插件

当前版本：v1.5.5

移植自 [maimaiDX](https://github.com/Yuri-YuzuChaN/maimaiDX) 项目（原基于 HoshinoBot/NoneBot）

## 功能特性

- 🎵 查询歌曲信息、定数、BPM、曲师、谱师
- 📊 查询玩家成绩、各类 B50、图形化牌子进度
- 🔀 多查分器数据源：支持 **水鱼查分器（Diving-Fish）** 与 **落雪查分器（Lxns-Network）** 自由切换
- 🔐 水鱼 OAuth：支持设备码链接与一次性确认码回填、短期令牌自动换取与缓存，兼容完整成绩查询
- 🧩 统一曲库：启动时将水鱼曲目与落雪曲目合并为 `Song` 模型，补全白谱 / 宴会場等数据，并供查询、绘图、猜歌和成绩计算共用
- 🎯 成绩统一：水鱼 / 落雪成绩先归一为 `PlayedResult`，再桥接为现有绘图模型
- 🖼️ 图形化查询：曲目搜索结果展示封面、版本、谱面类型及各难度定数；牌子进度展示总进度、分难度完成率和未完成曲目
- 容错与分数线图片：支持歌曲ID、别名、名称及中英文难度，展示判定达成率变化与各音符独立容错个数
- 完整帮助与更新通知：`maihelp` 自动生成单张完整帮助图，支持版本与新功能标签；首次加载及升级可向启用群发送更新内容
- 群功能控制：支持舞萌功能白名单，并保留独立的排卡开关与别名推送名单
- 👤 玩家信息：落雪 B50 支持展示真实头像、姓名框、称号颜色、段位与阶级，并标注成绩数据源
- 🏷️ 别名合并：柚子别名 + 落雪别名 + 本地别名启动时合并
- 🎮 猜歌游戏功能
- 🏪 机厅排卡功能
- nearcade 接入：直接发送 QQ 位置卡查询附近舞萌 DX 机厅；支持舞萌、中二、太鼓等分游戏报人数，并可选上传云端，查询与上传分别配置
- 🏷️ 别名管理和推送
- 📈 定数表和完成表查询
- 📋 排行榜查询
- 群单曲排行榜：自愿加入/退出，`wmrk <歌曲> [难度]` 返回成绩排名图片，支持水鱼与落雪，省略难度默认最高难度

### 群单曲排行榜

- `加入排行榜`：加入当前 QQ 群的单曲排行榜，记录当前 QQ 昵称。名单按机器人账号与群号隔离，不会自动加入其他群
- `退出排行榜`：仅取消自己在当前群的参与，不删除查分器绑定，也不影响其他群。即使本群关闭舞萌功能，仍可退出
- `wmrk <歌曲ID/名称/别名> [难度]`：查询本群已加入玩家的该谱面成绩。`wmrk` 与歌曲之间可省略空格，例如 `wmrk11667`、`wmrk11667 紫`、`wmrk歌曲名称 Master`；命令不区分英文大小写，开头可加 `/`

歌曲优先匹配完整名称或别名，没有精确匹配时按曲名包含关系查找；多个候选时列出曲名及 ID，提示使用更完整的名称、别名或 ID。难度放在最后并以空格分隔，可用绿/黄/红/紫/白（可加「谱」）或 Basic/Advanced/Expert/Master/Re:Master。省略难度时选择该曲实际存在的最高难度：有白谱选 Re:Master，否则选 Master 等最高可用谱面；不存在的难度不自动回退，暂不支持宴会场。

每位玩家沿用当前选择的水鱼或落雪数据源，并须满足原有授权、配置和隐私要求。仅查询本群主动加入的玩家；未游玩和查询失败的玩家不在表格内补0分，图片底部仅统计人数。按达成率降序、DX 分降序排序，两者相同并列排名。结果图包含封面、各难度定数（高亮所选难度）、昵称、四位小数达成率、DX 分、FC/FS 和评级；页头左侧展示曲名、ID 等信息，右侧展示所选谱面 DX 满分及一至五星的最低 DX 分（向上取整），星级、FC/FS 及评级图标复用持久化资源包中的 B50 素材，缺少图标时回退文字。每张图最多20名玩家，超过时逐页发送，排名连续编号，各页重复歌曲信息并标注 `Pages 当前页/总页数`。没有人游玩时只返回「本群暂无人游玩过『歌名』！」文本、不生成空榜图片；若存在查询失败，则单独提示失败人数，不将查询失败当作未游玩。

名单保存在持久化目录的 `song_ranking.json`，仅记录 QQ 号和加入时昵称，不额外保存成绩或查分器凭据，插件升级及重装后保留。单曲查询限制3路并发、每位玩家20秒超时；同群已有查询时不重复发起。退出后不再参与后续查询，查询期间退出的玩家也会在生成排名前排除。

### 3. 安装依赖

插件兼容 AstrBot `>=4.22,<5`。插件代码要求 Python 3.10 及以上；还需满足所使用 AstrBot 版本的 Python 要求。若插件加载时提示缺少依赖或自动安装失败，请在运行 AstrBot 的同一 Python 环境中手动安装：

安装 Python 依赖：

```bash
cd astrbot_plugin_maimaidx
pip install -r requirements.txt
```

安装 Chromium（用于 `ginfo` 谱面统计中的 ECharts 饼图；B50、容错、分数线和新版帮助图使用 Pillow 绘制）：

```bash
python -m playwright install --with-deps chromium
```

**注意**：在 Windows 上需要使用 `python -m playwright` 而不是直接使用 `playwright` 命令。

安装系统中文字体（用于 Chromium 图表的中文显示；以下为 Debian/Ubuntu 示例，Windows 通常已有中文字体，可跳过；这不能替代静态资源包内的字体）：

```bash
apt install fonts-wqy-microhei
```

### 4. 配置插件

#### 4.1 插件配置（通过 AstrBot 配置界面）

所有配置均在 AstrBot 的插件配置界面中完成：

配置界面按七类折叠展示：**基础设置、水鱼查分器、落雪查分器、别名服务、图片与素材、机厅与云端上报、位置查询**。下方保留原配置项名称，便于查找；编辑 JSON 时需放在对应分组中，例如 `arcade.arcade_data_source`、`divingfish.df_client_id`、`location.nearcade_radius_km`。

升级后首次加载会自动将旧版平铺配置迁移到相应分组，保留 Token、OAuth 凭据、开关、滑块及机厅映射，无需重新填写；已填写的非默认分组配置优先。旧根字段仅供迁移，界面中隐藏，迁移成功后清空旧副本，后续只读取分组配置。位置查询关闭时隐藏范围和个数，上传关闭时隐藏 Token 输入框；切换为 nearcade 数据源后隐藏不再需要的本地机厅映射，隐藏不会删除已保存的值。

**基础**

- `bot_name`: 机器人名称，用于在消息中显示（如：今日运势功能），默认为 "Bot"
- `update_notice`: 插件更新通知，默认开启；首次建立版本记录及升级时仅向已执行「开启舞萌功能」的群发送 changelog 中的新功能、优化、修复等内容，仅跳过「其他」分类；失败会在 60 秒后重试一次，仍失败则停止
- `maimaidxwhitelist`: 舞萌功能白名单，默认关闭；开启后仅允许管理员执行过「开启舞萌功能」的群使用舞萌功能，私聊不受影响；无论该开关是否开启，更新通知都只发送到这些明确开启的群
- `enable_reply`: 是否在多数指令回复中添加“引用消息”（Reply），默认为开启

**nearcade 机厅查询与人数上报**

- `arcade_data_source`: 机厅信息来源，可选 `local`（默认，原有本地机厅）或 `nearcade`（直接使用云端机厅库，无需本地机厅及云端映射）。修改后重载插件；两种来源的订阅、别名及报数缓存分别保存，首次切换需要重新订阅，切回后原订阅仍保留
- `nearcade_api_token`: 在 [nearcade API 令牌设置](https://nearca.de/settings/api-tokens) 中生成的 API Token，仅用于人数上报；不要在群聊中发送，位置查询和云端人数查询无需此凭据
- `nearcade_upload_enabled`: 是否将排卡人数变化上传 nearcade，默认关闭；需配置 Token，只有 `local` 数据源还需机厅映射
- `nearcade_location_enabled`: 是否直接响应 QQ 位置卡，默认关闭；开启后无需任何前置指令，群聊、私聊均可使用
- `nearcade_radius_km`: 附近机厅查询半径，默认5公里；使用1至30公里滑块，步长0.5公里，按直线距离过滤并排序
- `nearcade_result_limit`: 返回机厅个数，默认最多5家；使用1至20家滑块，步长1家
- `nearcade_game_aliases`: 仅 `nearcade` 数据源使用的机台别名列表，格式为 `云端机厅ID[别名]=gameId`，例如 `14871[mml]=14871002`、`14871[抬手乐]=14871000`。用于精确更新某条机台记录，不需要本地机厅 ID；普通游戏总人数报数不受影响。`local` 数据源忽略此配置
- `nearcade_shop_bindings`: 仅 `local` 数据源使用的云端机厅映射列表，`nearcade` 数据源忽略该配置。通常只需 `本地机厅ID=云端店铺ID`，同游戏多条记录按总人数自动分配；需要精确修改某条记录时，可增加 `123[mml]=456:456000`、`123[抬手乐]=456:456001` 等机台别名，无需游戏前缀，发送 `某机厅mml3` 即更新对应 gameId。仍兼容 `[mai]`、`[chu]`、旧版舞萌专用格式及原有命名映射，详见下方使用说明

两个功能开关相互独立，均默认关闭。配置保存并重载插件后生效；Token 由 AstrBot 插件配置管理，插件不复制到额外的持久化文件或日志。

**水鱼查分器（Diving-Fish）**

- `df_client_id`: 水鱼 OAuth 应用的 client_id
- `df_client_secret`: 水鱼 OAuth 应用的 client_secret。请仅保存在 BOT 配置中，不要提交到公开仓库
- `maimaidxtoken`: 旧版水鱼开发者 Token，仅供迁移期兼容；官方当前计划于 2027-01-01 停止服务
- `maimaidxproberproxy`: 是否使用中转访问水鱼查分器（适用于境外服务器），默认关闭

> 水鱼 OAuth 配置：登录[水鱼开发者控制台](https://auth.diving-fish.com/console)。已有 Developer-Token 的管理员补全系统迁移生成的应用；没有迁移应用则为当前 BOT 实例登记新应用。接入方式选择“设备码”，权限仅选择 `prober.records.read`，然后生成 `client_secret`。未迁移授权关系的用户需要发送「绑定水鱼」完成一次授权。公开 `b50` 查询不要求绑定，AP50、拟合 B50、完成表、进度及单曲成绩等完整成绩功能需要授权。

#### 从 Developer-Token 升级到 OAuth（v1.4.0）

水鱼已停止签发 Developer-Token，官方当前计划于 **2027-01-01 00:00（UTC+8）** 停止旧版 `/dev/player/records`、`/dev/player/record` 与 `/query/plate` 接口。升级步骤：

1. 登录[水鱼开发者控制台](https://auth.diving-fish.com/console)，补全迁移应用或登记新应用。
2. 接入方式选择“设备码”，仅申请 `prober.records.read` 权限，并生成 `client_secret`。
3. 在 AstrBot 插件配置中填写 `df_client_id` 与 `df_client_secret`，然后重载插件。
4. 未自动迁移授权关系的用户发送「绑定水鱼」，打开返回的链接并确认应用与绑定身份，登录并同意后，将网页显示的一次性确认码通过「水鱼授权码 XXXX-XXXX-XXXX」发回 BOT；BOT 返回绑定成功后即可查询完整成绩。

> 水鱼应用的接入方式仍选择「设备码」，不需要添加回调地址。插件使用 `handoff=code`：点击链接后还需由发起绑定的账号回填确认码才能完成绑定。只使用自己授权页面显示的码，不要复制别人发来的码。待绑定会话按平台、机器人账号、用户和查分器区分，群聊中发起后可在同一机器人的私聊中回填；插件重载或会话超时后需重新发起。

迁移期间可以继续保留 `maimaidxtoken`；当 OAuth 配置完整时，插件会优先使用 OAuth 新接口。`client_secret` 只应保存在 BOT 配置中，禁止提交到公开仓库。

**别名 / 素材 / 性能**

- `maimaidxaliaspush`: 是否开启别名推送，默认开启
- `maimaidxaliasproxy`: 是否使用中转访问柚子别名服务器（适用于境内服务器），默认关闭
- `maimaidxaliaswhitelist`: 别名推送是否采用白名单（默认关闭）。开启后仅向已执行「开启别名推送」的群广播；关闭时为「全群推送 + disable 黑名单」
- `saveinmem`: 是否将部分图片保存在内存中，默认开启（`false` 可节省内存，但生成稍慢）
- `assets_online`: 是否在线获取素材，默认开启（有本地 icon/plate 素材时可设为 `false`）

**落雪查分器（Lxns-Network，可选，用于支持第二数据源）**

- `lxns_dev_token`: 落雪查分器开发者 Token。填写后用户即可用「数据源 落雪」按 QQ 号查询（需用户提前在落雪绑定 QQ 号，并在「隐私设置」中允许第三方读取成绩）。支持 b50 / ap50 / 单曲成绩 / 完成表 / 进度 等功能
- `lx_client_id`: 落雪 OAuth 应用的 client_id（可选，OAuth 权限仅需选择 `read_player`）
- `lx_client_secret`: 落雪 OAuth 应用的 client_secret（可选）
- `lx_redirect_uri`: 落雪 OAuth 回调地址（可选）。推荐在落雪开发者面板选择“无回调地址”并填写 `urn:ietf:wg:oauth:2.0:oob`；留空时插件也会自动使用该地址。请勿填写完整的 OAuth 授权链接

> 说明：仅配置 `lxns_dev_token` 即可让用户按 QQ 号查询落雪成绩；若额外配置 OAuth 应用（`lx_client_id` 与 `lx_client_secret`），用户可通过「绑定落雪」进行授权，获取含**精确达成率**的完整成绩，从而支持「分数列表」「我要上分」等功能。选择“无回调地址”后，落雪会在授权成功页直接显示授权码；插件使用的回调 URI 为 `urn:ietf:wg:oauth:2.0:oob`。插件会在 Access Token 失效时自动刷新并保存落雪返回的新令牌。详见[落雪 OAuth 接入指南](https://maimai.lxns.net/docs/oauth-guide)。

### 5. 配置管理员

在 AstrBot 主配置文件中设置管理员ID列表（字段名为 `admins_id`），用于执行更新数据等管理命令。

**注意**：管理员ID配置在 AstrBot 的主配置文件中，不在插件配置中。

### 6. 启用插件

将插件目录放置在 AstrBot 的插件目录下，重启 AstrBot 即可。

## 主要命令

发送 `maihelp` 可查看代码生成的单张完整帮助图，包含查歌、成绩、授权、容错、牌子、猜歌、别名、机厅及管理命令；不再依赖手工更新帮助图片。

新版完整帮助图仅通过 `maihelp` 触发；`帮助maimaidx` / `helpmaimaidx` 显示旧版 `maimaidxhelp.png`。以上入口均不区分英文大小写，开头可加 `/`，例如 `/maihelp`、`MAIHELP`、`帮助maimaiDX`。排卡专用帮助改为 `排卡帮助`（也可加 `/`，群内需先开启排卡）。新版图缺少字体时会尝试回退旧图。

帮助图标题后显示当前完整版本号，指令末尾的粉色「新」标签按「主版本号 + 次版本号」归类：例如在 1.5.5 中，1.5.1 至 1.5.5 新增或升级的功能都会显示「新」；1.5.x 内更新保留标签，升至 1.6.x 或 2.x 后不再标记旧系列的功能。

帮助图沿用原图的粉色标题和彩色背景风格。`※` 标记前置参数或开关指令，`#` 表示管理员专用（AstrBot 配置的管理员），`☆` 表示群管理员可用（群主或群内管理员）；管理员同样可以使用全部 `☆` 指令，符号无需输入。群聊专用指令仍需在群内使用。

成绩查询统一使用 `[玩家]` 参数，可填写 QQ 号、实际 @群成员或水鱼用户名，省略查询自己。实际 At 优先于文本参数；用户名查询使用水鱼，QQ/At 查询按目标玩家的数据源设置。含金量、水分分析、单曲成绩、完成表、进度、分数列表及上分推荐均支持此写法；带分页的命令可使用 `[页码] [玩家]`，单独填写至少五位的纯数字时按 QQ 号处理。容错计算、分数线也支持英文难度名：Basic / Advanced / Expert / Master / Re:Master，分别对应绿 / 黄 / 红 / 紫 / 白。

### 机厅功能

**选择机厅数据源：** 在 AstrBot 插件配置中设置 `arcade_data_source` 后重载插件。

- `local`：默认方式，使用原有本地机厅库，可添加、删除、修改本地机厅；需要同步或读取 nearcade 人数时配置映射。
- `nearcade`：直接从 nearcade 查找和订阅机厅，使用云端店铺 ID，不要求本地存在该店，也不需要映射。查找及人数查询无需 Token；上传仍需配置 Token 并开启 `nearcade_upload_enabled`。

nearcade 模式可依次使用 `查找机厅 金沙` → `订阅机厅 <云端ID>` → `<云端ID>mai3chu2` → `机厅几人`。报人数仍限于本群已订阅机厅，须先开启排卡；完整店名、别名和 ID 均可使用。多个候选不会自动选第一家，需要指定 ID；搜索最多返回20家，可缩小关键词重查。两种来源的订阅、别名与本地报数分别保存，切换不会自动迁移或混用同号 ID。

nearcade 模式的机厅、地址及机台数量直接来自云端，新增/删除机厅及修改数量请在 [nearcade 网站](https://nearca.de/shops) 维护，插件不会修改另一套本地目录。官机、MML、手台等舞萌 DX 仍属于同一游戏类别，普通游戏报数按同类记录总人数分配，不自动生成分区。`机厅几人` 总览及单店详情按云端游戏记录逐条展示，不再合并同类记录的人数，名称采用「游戏名（version）」，例如 `舞萌 DX（CN1.56-A）`、`舞萌 DX（mml）`、`舞萌 DX（adx）`；版本为空只显示游戏名，不使用 gameId 命名。总览仅列人数，单店详情另含机台数等信息。报数使用 `某机厅3`、`某机厅mai3`、`某机厅chu2` 等格式，旧版自动分区缓存也会合并。

同类别多条记录按**游戏总人数**上传，采用最少改动策略：先读取当前各条人数，增加和减少均优先调整人数最多的，相同时优先人数接口返回顺序靠前的；减少不足再扣下一条，每条最低为0，尽量保持其他记录不变。调整后各条之和等于汇报总人数，只上传变化的记录，不改其他游戏。例如当前舞萌分别为 `2、5、1` 人，汇报10人后为 `2、7、1`，汇报6人后为 `2、3、1`，汇报4人后为 `2、1、1`，汇报1人后为 `0、0、1`；原来为 `3、3、3` 人，汇报8人后为 `2、3、3`。本地通用映射同样适用，显式指定 gameId 的旧映射仍只更新所选记录，不提供按 version 匹配报数，以免不同游戏版本同名产生歧义。无法核对完整云端数据时不上传，并明确返回失败原因；不会把同一总人数写入每条记录造成翻倍。

开启上传时，nearcade 模式报数会先核对云端当前人数，`+1/-1` 不使用旧缓存；读不到当前人数时停止该项，不盲目覆盖云端。尚未上报的游戏需先 `=人数`。未开启上传时仍可保存本地报数，但查询优先展示云端人数，只有云端读取失败才明确标注并回退本地；关闭上传并不等于切回本地数据源。云端模式的订阅及报数缓存在持久化数据目录的 `nearcade_arcades.json` 中，不保存 API Token。

以下添加、删除、修改数量及手动命名映射分区的说明适用于 `local` 数据源，其余查询及报数指令两种来源共用：

- `开启排卡` / `关闭排卡` - 按群开启/关闭排卡功能（管理员或群管理员可用，默认关闭）
- `排卡帮助` - 查看机厅帮助
- `添加机厅 <店名> <地址> <机台数量> [别名]` - 添加机厅（管理员）；可选多个别名，用空格分隔
- `查找机厅 <关键词/ID>` - 查找机厅，本地与 nearcade 数据源均无需开启排卡；仍遵守舞萌功能白名单及禁用群设置
- `订阅机厅 <店名/ID/别名>` / `取消订阅机厅 <店名/ID/别名>` - 管理本群订阅（管理员或群管理员）
- `查看订阅` - 查看本群已订阅的机厅
- `修改机厅 <店名/ID> [游戏/分区名] 数量 <机台数量>` - 修改所选游戏的本地机台数量（管理员或群管理员），省略游戏仍修改舞萌；例如 `修改机厅 123 chu 数量 2`、`修改机厅 123 maiA区 数量 1`。本地回执及本地查询使用这些数量，云端查询优先使用 nearcade 的实际数量；配置不会虚构人数上报，设置0表示本地暂无可用机台
- `删除机厅 <完整店名>` - 删除机厅（管理员）
- `添加机厅别名 <店名/ID> <别名>` / `删除机厅别名 <店名/ID> <别名>` - 管理机厅别名；本地模式填写本地机厅 ID，nearcade 模式填写云端店铺 ID，例如 `添加机厅别名 14871 萌动`
- `添加群机厅别名 <店名/ID> <别名>` / `删除群机厅别名 <店名/ID> <别名>` - 管理仅当前群生效的机厅别名（管理员或群管理员），添加前必须先让本群订阅该机厅，例如先 `订阅机厅 456`，再 `添加群机厅别名 456 天街`；兼容本地和 nearcade 数据源，各自独立保存，不修改全局别名及其他群。支持用本群别名查找、订阅、查人数或报人数，如 `查找机厅 天街`、`订阅机厅 天街`、`天街几人`、`天街mai3chu2`；报数仍要求本群已订阅机厅，取消订阅后仍可删除旧群别名
- `<机厅名/别名> [游戏]=人数` / `<机厅名/别名> [游戏]+人数` / `<机厅名/别名> [游戏]-人数` - 设置或增减该游戏排卡人数，例如 `机厅mai=5`、`机厅 chu+1`、`机厅太鼓-1`；游戏前可不加空格，省略游戏默认舞萌 DX
- `<机厅名/别名> [游戏]<人数>[人/卡]` - 直接设置人数，例如 `某机厅3`、`某机厅mai3`、`某机厅3人` 都等同于 `某机厅=3`，默认更新舞萌；`某机厅中二3` 只更新中二。店名以数字结尾时，建议用空格或 `=` 分隔人数；使用纯数字 ID 时需用空格、`=`、游戏名或「人/卡」区分 ID 与人数，如 `123 3`、`123=3`、`123mai3`、`1233人`，纯数字消息不报数
- `<机厅名/别名>游戏人数游戏人数` - 同时报多个游戏，例如 `某机厅mai3chu2` 将舞萌设为3人、中二设为2人；也支持 `某机厅 mai3 chu2 太鼓1`。数字默认是总人数，不是增加人数；各项也可写 `=人数`、`+人数`、`-人数`。旧命名映射的报数示例见下方仅 local 模式的兼容说明
- `<机厅名/别名>[游戏]=-1` - 将所选游戏的本地排卡标记为闭店并清空该游戏人数，省略游戏默认舞萌，不影响其他游戏或云端营业状态；人数恢复到 1 以上时自动恢复营业，设置为 0 时保持闭店
- `机厅几人` - 本群订阅的机厅按店名分组，各游戏人数逐行缩进列出，机厅之间空行分隔，方便手机阅读；`某机厅几人` 查看详细信息，支持 `某机厅mai几人`、`某机厅chu几人`、`某机厅太鼓几人` 筛选。配置映射的店优先从 nearcade 读取当前人数和机台数量，无需 Token、不依赖上传开关；未映射或查询失败时使用本地记录并标注来源，查询不上传或修改人数

单机厅人数查询格式为 `<机厅名/别名/ID> [游戏]几人`，也支持 `某机厅几`、`某机厅j`、`某机厅jr` 等简写。机厅名称可换成ID、全局别名或本群别名；本地模式使用本地机厅 ID，nearcade 模式使用云端店铺 ID，例如 `14871几人`、`14871mai几人`、`14871chujr`。也可指定游戏，如 `天街chu几`、`天街chujr`；原有「有多少人／有几人／有几卡／多少人／多少卡／几卡」后缀继续支持，并补充「有几」。不带机厅参数的 `机厅几人` 或 `jtj` 则用于本群订阅总览，只回复一次。

`查看订阅` 和 `机厅几人`（含 `jtj`）在本地和 nearcade 模式统一处理长列表：超过1000字或30行（含空行）时，在 QQ 上合成一条聊天记录，每家机厅单独一个节点；单家内容超过1500字时继续拆分，不截断内容。未达到折叠条件时发送普通文本，本地订阅的开头提示在聊天记录中单独一个节点；其他平台按长度分条发送普通文本。

插件运行期间每天凌晨3点（运行环境时区）刷新机厅资料后，将本地舞萌、中二及其他已记录游戏的人数清零，并清理当前 nearcade 数据源的本地备用缓存。订阅、全局/群别名、机台数量和闭店状态保持不变，旧报数者及时间清除并标记为「系统每日清零」。资料刷新失败仍尝试清零，保存失败会恢复原人数并记录错误；整个清零过程不上传 nearcade。nearcade 模式和已配置映射的本地机厅查询优先云端，云端失败才回退本地缓存；未配置映射的本地机厅直接使用本地记录。

报人数和查询均支持舞萌/mai、中二/chu、太鼓/taiko、音律炫动/sdvx、iidx、音击/ongeki、华卡/wacca、jubeat/jb、ddr、dancerush/drs、nostalgia、音炫轨道/gc、piu、初音/diva。英文不区分大小写；各游戏人数、更新者、时间和闭店状态独立保存，不混入舞萌人数。太鼓和 jubeat 兼容云端的新旧系列记录，nearcade 模式按云端游戏记录展示人数，普通游戏报数仍按同类总人数分配，不生成分区名；local 模式仍兼容已有的手动映射。

群里只订阅了一家机厅时，可以省略店名，如 `chu=5`、`mai3`；订阅多家时必须指定店名、别名或当前数据源的机厅 ID，避免同时改动多个机厅。不带游戏名的指令和原有数据继续按舞萌 DX 处理。两种模式均可选用机台别名精确报数；local 旧版按游戏命名的分区映射仍兼容原来的指定映射名规则，nearcade 模式无需分区名。

群机厅别名可在不同群重复使用并指向不同机厅，本群别名优先于全局别名；同群不能用同一个别名指向多家机厅，也不能冒用另一机厅的完整名称。别名最多40个字符，不含空格，不能为纯数字或「机厅」，数字仍作为机厅 ID 使用。「查看订阅」会单独显示本群别名，不展示其他群的别名；删除群别名只删除本群记录，同名全局别名仍然有效。群别名本身不代表订阅或改变排卡开关。

批量报数会先校验整条格式；格式不完整、出现未识别的后续游戏名或同一游戏/分区重复填写时，不更新任何人数。格式正确后逐项执行，某项人数超过单次变化30人的限制、需要指定分区或本地保存失败，不影响其他合法项；本地保存失败的项恢复原人数、不上传云端。最多同时提交16项，同一机厅的整批报数顺序执行，避免和其他报数交错。

更新与查询采用机厅、游戏人数、机台数量及「更新者 · 时间」的分块布局，参考 [nonebot_plugin_mai_arcade 的人数回复](https://github.com/YuuzukiRin/nonebot_plugin_mai_arcade/blob/main/nonebot_plugin_mai_arcade/handlers/count.py)。单项更新显示「人数已更新为」，查询显示「当前人数」，批量报数在各游戏条目中保留独立的本地与云端结果。以舞萌5人、中二3人且各自均有2台机为例，开启云端上传后的批量回复如下：

```text
📍 机厅：某机厅
🎮 舞萌 DX：本地更新成功，当前 5 人；云端同步成功
🕹️ 机台数量：2 台
（玩家A · 2026-10-19 15:00:00）

🎮 中二节奏：本地更新成功，当前 3 人；云端同步成功
🕹️ 机台数量：2 台
（玩家A · 2026-10-19 15:00:00）
```

若某一项上传失败或结果未确认，该项会明确提示「云端未确认同步：原因（本地记录保留）」；若本地校验或保存失败，会提示「更新失败：原因」。未开启上传时提示「未开启云端上传」，人数无变化时提示「人数未变化；未重复上传」，闭店时提示「本地已闭店；未上传云端」。第一次明确上报0人也会记录并按配置上传，不再与尚未上报混淆；重复报相同人数不会自动重试之前失败的云端同步。

报人数回执和人数查询均不显示预计等待、每轮时间、轮次范围、每轮容量及出勤建议，也不再附带「暂不估算等待时间」等提示，避免官机、MML、手台等实际游玩容量不同导致误导；保留人数、机台数量、更新者、更新时间和云端同步结果。云端查询直接使用对应游戏的当前机台数量，本地回执与回退查询使用「修改机厅」设置的数量；其他游戏和命名分区不会借用舞萌总机台数。云端读取只用于本次显示，不覆盖本地人数、更新者、时间或机台配置，也不触发上传。

发送 `机厅几人` 时使用简洁总览，不显示机台数、等待估算和更新者，例如：

```text
店名：A机厅
  - 舞萌 DX（CN1.56-A）：3人
  - 舞萌 DX（mml）：2人
  - 中二节奏：3人
  - 太鼓达人：未上报

店名：B机厅
  - 舞萌：6人

店名：C机厅
  - 数据来源：本地·云端查询失败
  - 舞萌：2人

店名：D机厅
  - 数据来源：本地
  - 舞萌：未上报
```

详细布局仅用于单店或指定游戏查询。local 模式云端读取使用已核对的 `nearcade_shop_bindings`，不会按相似店名猜测；nearcade 模式直接使用云端 ID。同一云端店铺在一次人数查询中只读取一次，总览过长时按上述规则折叠为聊天记录。人数取自云端各条游戏记录的综合在勤 `total`，不会把店铺总人数当舞萌人数；nearcade 展示时逐条列出，普通游戏报数所用的同类总数及最少改动分配规则不变。local 模式仍按现有游戏及映射展示，云端失败时本地缓存没有逐条记录明细，不会伪造 version 或拆分人数。无在勤也无当前上报的记录显示未上报，明确上报0人则保留0人。云端请求失败只影响对应店铺，详细查询会说明原因；其余店正常返回。

### QQ 位置卡与云端机厅

开启 `nearcade_location_enabled` 后，直接发送 QQ 原生位置卡（或标准位置消息）即返回附近有舞萌 DX 的机厅，不需要先发送任何文字指令。每家机厅按「🎮 名称（距离）」与「📍 地址」两行展示，不足1公里显示米，其余显示公里，机厅之间空行分隔。末尾统一附上「👉 更多详情请点开」链接，自动带入本次经纬度、查询范围、GCJ-02 坐标转换及舞萌 DX 筛选，不再附带位置名称，避免中文编码使链接过长；营业状态和人数等详情可点开查看，结果较多时按机厅条目分条发送。普通聊天、其他 JSON 卡片及不含有效坐标的位置卡不会触发查询。

位置查询不依赖本群排卡开关，也不要求订阅机厅，但仍遵守舞萌功能白名单和禁用群设置。QQ 坐标按 GCJ-02 向 nearcade 查询，并用于生成回复中的详情链接，不写入插件持久化文件；群聊内其他成员也能通过该链接看到本次查询的位置，系统或消息平台自身的日志不在插件控制范围内。

**云端人数上传配置步骤（local 数据源）：**

使用 `nearcade` 数据源时，跳过以下本地机厅查找和映射步骤：直接查找并订阅云端 ID，填写 Token、开启上传即可。

1. 登录 nearcade，绑定手机号并在设置中生成 API Token，填写 `nearcade_api_token`；已认领机厅需要有权上报该店铺的专用凭据。
2. 通过 `查找机厅 <关键词>` 确认本地机厅 ID；打开 [nearcade 机厅列表](https://nearca.de/shops)，核对地址及机台后，从详情链接 `https://nearca.de/shops/数字` 获取云端店铺 ID。两边 ID 不可混用。
3. 在 `nearcade_shop_bindings` 添加映射。示例 `123=456` 表示将本地机厅123对应到云端店铺456；这是格式示例，请替换成实际核对过的 ID，不会按相似店名自动匹配。
4. 通常到这里即可：插件按指令中的游戏自动选择云端对应记录；一条舞萌加一条中二不会造成歧义，一条记录包含多台实体机也无需额外指定。同类多条记录默认按总人数最少改动分配。通过 `https://nearca.de/api/shops/云端店铺ID` 查看 `shop.games`，按 `titleId` 核对游戏系列、`gameId` 核对具体记录。需要精确更新时可用 `123[mai]=456:456000` 或 `123[chu]=456:456001` 指定记录；旧命名映射的兼容方式见下方。旧格式 `123=456:456000` 的具体 gameId 仅用于舞萌，其他游戏只继承店铺 ID，不会误用舞萌的 gameId。
5. 开启 `nearcade_upload_enabled` 并重载插件。在已开启排卡并订阅该机厅的群里，人数变化成功后会自动上传最终人数；回复中显示是否同步成功。

**nearcade 模式机台别名（可选）：**

在「机厅与云端上报」配置的 `nearcade_game_aliases`（JSON 路径为 `arcade.nearcade_game_aliases`）中填写：

```text
14871[mml]=14871002
14871[抬手乐]=14871000
```

左侧数字直接是 nearcade 云端机厅 ID，方括号内是自定义机台别名，右侧是该机厅内的 gameId，不需要填写本地 ID 或通用映射。重载插件并订阅该机厅后，可发送 `14871mml3`、`14871抬手乐4`、`14871mml+1`、`14871mml3抬手乐4`，也可将 ID 换成店名或机厅别名；`14871mml几人` 查询指定记录。

机台别名不要求游戏前缀，实际游戏按 gameId 的云端资料确认；同机厅的别名与 gameId 均不能重复，别名不能使用 `mai`、`chu`、`舞萌` 等现有游戏名，以免覆盖总人数指令。不同机厅可以使用相同别名，不按 version 自动匹配。普通 `14871mai8` 仍调整舞萌总人数，nearcade 的 `机厅几人` 与详情逐条显示游戏名和 version，别名不会作为额外记录重复展示。两种数据源的别名配置相互独立，切换数据源不会混用。

**local 模式机台别名（可选）：**

方括号内可以直接填写机台别名，不必以游戏名开头。别名对应右侧明确指定的 gameId，插件通过云端机台资料确认所属游戏，不根据别名或 version 猜测。例如本地机厅123对应云端「萌 动」14871：

```text
123=14871
123[mml]=14871:14871002
123[抬手乐]=14871:14871000
```

可以发送 `某机厅mml3`、`某机厅抬手乐4`，分别将对应记录设为3人、4人，也支持 `某机厅mml+1`、`某机厅抬手乐-1`、`某机厅mml3抬手乐4` 和 `某机厅mml几人`。保留通用映射 `123=14871` 时，普通 `某机厅mai8` 仍按舞萌总人数最少改动分配；机台别名不会使普通游戏报数变成必须指定分区，总览也不会把别名记录重复计入游戏总数。

两种模式的机台别名均限1至40个字符，不能包含空格、运算符或为纯数字；英文大小写不敏感，同一家机厅不能配置重复别名。不同机厅可以使用相同别名，由指令中的机厅名或 ID 区分；同一机台不要重复配置多个别名映射。首次使用或插件重载后，需要联网读取公开机台资料确认游戏类型，读取无需 Token；确认失败或 gameId 不存在时不修改人数。关闭上传后仍可本地报数，但首次确认类型也需要联网；开启上传后按该 gameId 的云端人数核对增减，不借用其他机台的缓存。

`[mai]`、`[chu]` 等原有按游戏指定记录的写法继续兼容；下方旧游戏前缀分区名也仍可使用。

**旧命名映射兼容（仅 local 模式）：**

此方式仅供已有本地命名映射继续使用，nearcade 模式不会读取或生成这些分区。新配置通常使用上面的通用映射或按游戏指定 gameId 即可，无需命名分区。

例如本地机厅123的舞萌在云端分成A、B两条记录，配置为：

```text
123[maiA区]=456:456000
123[maiB区]=456:456001
123[chu]=456:456002
```

两条分区共用本地机厅ID，不需要另建机厅或重复订阅。方括号内的映射名以游戏名开头、后接分区名，最长40个字符，例如 `maiA区`、`maiB区`、`chu一楼`；分区映射必须指定 gameId，不同分区不得指向同一个云端游戏记录。输入 `某机厅maiA区5人`、`某机厅maiB区3人` 或 `某机厅maiB区+1`，分别更新对应分区。配置了分区的游戏不能再省略分区报人数，插件会提示可用映射名，避免误写或重复上传；其他未分区游戏不受影响。即使暂时关闭云端上传，已有分区配置仍可用于本地报数。

`某机厅几人` 详细列出该店游戏、分区；`机厅几人` 则按店名分组、各游戏人数分行简洁列出；`某机厅mai几人` 仅列舞萌记录，`某机厅maiA区几人` 仅列A区。云端查询按映射返回相应游戏、分区的数据，当前云端人数和机台数不依赖本地配置是否及时更新；通用映射读取店内各游戏，只有显式游戏/分区映射时只读这些映射。如需命名舞萌分区同时自动展示店内其他游戏，可保留 `123=456` 通用映射并添加 `123[maiA区]` 等分区映射。回退本地时，原有未分区舞萌记录会单独标明、不当作分区合计，不自动拆分或覆盖分区人数。

上传的是所选游戏、分区的实际人数绝对值，不包含群号、QQ号或昵称，也不会自动为用户登记在勤。未配置舞萌分区时，未指定游戏默认上传舞萌 DX 人数，中二及太鼓人数不会覆盖舞萌。上传失败仍保留本地更新；不自动重试旧人数，避免覆盖更新后的数据。`=-1` 仅将当前游戏、分区的本地排卡标记为闭店，不向云端发送负数或修改永久闭店状态；查询、重复设置相同人数、无效输入和定时清零不会触发上传。云端可因凭据、手机号、认领状态或营业时间拒绝请求。

nearcade 按游戏记录分别保存人数，也可汇总为店铺总人数。`titleId` 表示游戏系列（舞萌 DX 为1、中二节奏为3、太鼓为31或旧版15），`gameId` 表示该店铺里具体的一条游戏记录，`quantity` 则是该记录的实体机数量。本插件只上报指令指定的游戏，不修改其他游戏，也不把整个店铺人数当作舞萌人数；位置卡查附近机厅仍筛选舞萌 DX。

同一 BOT 的同一机厅更新按顺序执行；多个 BOT 或网站用户之间没有跨端事务保证，后续上报仍可能覆盖前次人数，应以现场实际人数为准。

- 首次不存在记录时建立版本记录并广播当前版本 changelog 的更新内容，不发送全部历史日志
- 当前版本高于已记录版本时，提取两者之间各版本的新功能、优化、修复及说明等更新内容，仅跳过「其他」分类及其子标题；没有新功能但有优化或修复的版本同样展示具体内容，无可广播内容时作简短提示。消息保留分类标题与完整日志链接，不截断跨版本更新内容。发送范围始终为已执行「开启舞萌功能」的群，不受舞萌白名单、别名推送或排卡开关影响
- 等待 OneBot / aiocqhttp 连接就绪，逐群发送，群间间隔2秒；失败会在60秒后重试一次，仍失败则停止该版本通知并记录完成状态，已成功并记录的群不会重复发送
- 多机器人按平台分别记录进度；群开关在每次发送前重新检查，同版本已完成通知后重载不重复广播，未完成且尚未耗尽重试次数的通知会在重载后继续；版本降级不触发广播
- 更新通知统一发送为一条 QQ 合并转发（聊天记录），首次通知、单版本和跨版本更新均适用；开头的版本提示单独作为一个节点，随后每个版本另起节点，过长时优先按换行拆分，每个节点不超过1500字，单行超过上限时按长度拆分。完整更新日志链接、帮助和反馈渠道固定放在最后一个独立节点：日志链接后空一行提示「功能使用说明请通过 /maihelp 查看。」，最后一行附上功能建议与问题反馈渠道：邮箱 `contact@zhihezier.com` 或[项目 Issue](https://github.com/ZhiheZier/astrbot_plugin_maimaidx/issues)；可通过插件配置中的 `update_notice` 关闭通知
- 记录文件异常时保留原文件并停止通知；禁用群配置读取异常时不广播，避免误发。无需手工创建或删除 `version.json`

### 舞萌功能白名单

- 在插件配置中开启 `maimaidxwhitelist` 后，群聊默认不可用；由管理员在目标群发送 `开启舞萌功能` 加入白名单，发送 `关闭舞萌功能` 移出并禁用
- 名单与禁用群一起保存在持久化目录的 `disabled_groups.json`，独立于别名推送白名单与排卡开关；旧文件无需手工修改，已有禁用群设置会保留
- 白名单关闭时仍默认全群可用、排除已关闭的群；此时执行「开启舞萌功能」也会记录明确开启的群，方便以后切换白名单模式
- 更新通知始终只发送到此名单中的群，不受舞萌白名单开关影响；私聊不受群白名单限制

### 其他

1. **首次使用**：首次使用需要执行 `更新定数表` 和 `更新完成表` 命令生成相关数据
2. **资源文件**：必须下载并配置静态资源文件，否则部分功能无法使用
3. **别名推送**：群开关与全局推送指令用于控制群广播，不等于停用所有别名数据更新；也可通过 `更新别名库` 手动刷新
4. **内存配置**：`saveinmem` 设置为 `false` 可节省内存，但 Best 50 图片生成会稍慢
